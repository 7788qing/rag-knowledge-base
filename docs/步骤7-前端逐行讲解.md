# 步骤 7 代码逐行讲解：《app/ui/app.py》在做什么

> 配合 `app/ui/app.py` 一起看。
> 看不懂某一句，直接复制给助手问。

---

## 0. 一句话

前端**不碰数据库、不碰模型**，只做一件事：调 FastAPI 的接口。

```
浏览器 ←→ Streamlit（app/ui/app.py）←→ FastAPI（app/main.py）←→ Chroma / DeepSeek
```

为什么要绕这一圈？
- 后端只有一份，前端可以换（今天是 Streamlit，以后可以换 Vue）。
- 前端崩了，数据不会坏。
- 这就是「前后端分离」，面试常问。

---

## 1. 先认识 Streamlit 的三个脾气

| 脾气 | 意思 | 影响 |
|---|---|---|
| 脚本会**整份重跑** | 你点任何按钮，Python 文件从第 1 行跑到最后一行 | 普通变量会被重置 |
| 想留住数据用 `st.session_state` | 一个跨重跑的「记忆字典」 | 聊天记录必须放这里 |
| 用组件拼页面 | `st.write` / `st.button` / `st.chat_input` | 不用写 HTML/CSS |

记住第一条，后面全通：**每次交互 = 重新执行整个脚本**。

---

## 2. 开头：配置和 HTTP 封装

```python
API = os.getenv("API_BASE_URL", "http://127.0.0.1:8000")
TIMEOUT = 180.0
```

- 后端地址从环境变量读，默认本机 8000。
- 部署到服务器时改环境变量即可，代码不动。
- `TIMEOUT=180` 秒：上传大文件、等模型回答都要时间。

```python
def api_post(path, json=None, files=None):
    return httpx.post(f"{API}{path}", json=json, files=files, timeout=TIMEOUT)
```

- 就是把「网址 + 参数」拼起来发出去。
- `json=` 用于问答；`files=` 用于上传文件。

```python
def fetch_health():
    try:
        resp = api_get("/health")
        return resp.json() if resp.status_code == 200 else None
    except httpx.HTTPError:
        return None
```

- 连不上就返回 `None`，**不让前端崩**。
- 这是前端的铁律：后端挂了，页面也要能打开，并且告诉用户为什么。

## 3. 侧边栏：一眼看到状态

```python
with st.sidebar:
    health = fetch_health()
    if health:
        st.success("后端已连接")
        st.metric("已入库块数", health["chunks"])
```

- `with st.sidebar:` 里面的东西都放左边。
- `st.metric` 是一个大数字卡片。
- 有数字，你就知道「库里有几块」——调试时最有用。

## 4. 页签一：问答

### 历史消息的存法

```python
if "messages" not in st.session_state:
    st.session_state.messages = []
```

- 第一次运行，初始化一个空列表。
- 之后每次重跑，`session_state` 还在，聊天记录不丢。

### 重绘历史

```python
for msg in st.session_state.messages:
    with st.chat_message(msg["role"]):
        st.markdown(msg["content"])
```

- 每次重跑都要把所有历史重画一遍。
- `msg["role"]` 是 `user` 或 `assistant`，决定气泡在左还是右。

### 收到提问

```python
question = st.chat_input("例如：迟到怎么算？")
if question:
```

- `st.chat_input` 固定在页面底部，像微信输入框。
- 用户按回车才有值，否则是 `None`。

```python
resp = api_post("/api/ask", json={"question": question})
data = resp.json()
st.markdown(data["answer"])
for cite in data["citations"]:
    st.caption(f"[{cite['index']}] {cite['doc_name']} · 第{cite['page_no']}页")
```

- 答案用 markdown 渲染（模型会给加粗、列表）。
- 引用用小字显示在下面——这就是「可溯源」的用户体验。

### 为什么要再 append 一次

```python
st.session_state.messages.append({...})
```

- 不存的话，下一次点按钮，这段回答就消失了。
- 因为脚本重跑，页面上的一切都是「重新画的」。

## 5. 页签二：文档管理

```python
uploaded = st.file_uploader("选择文件", type=["pdf", "docx", "md", "markdown", "txt"])
```

- `type=` 是白名单，和后台的 `ALLOWED_SUFFIX` 呼应。
- 前端先拦一道，用户少走弯路。

```python
files = {"file": (uploaded.name, uploaded.getvalue(), uploaded.type)}
resp = api_post("/api/documents", files=files)
```

- 这就是 HTTP 的 multipart 表单格式。
- 键名必须是 `file`，因为后端写的是 `file: UploadFile = File(...)`。

```python
if c4.button("删除", key=f"del::{doc['doc_name']}"):
    api_delete(f"/api/documents/{doc['doc_name']}")
    st.rerun()
```

- 每行一个删除按钮，`key` 必须唯一，否则 Streamlit 会报「重复 ID」。
- 删完 `st.rerun()` 立刻刷新页面。

## 6. 怎么跑起来（两个终端）

**终端 1（后端）**
```
python -m uvicorn app.main:app --reload
```

**终端 2（前端）**
```
streamlit run app/ui/app.py
```

浏览器会自动打开 `http://localhost:8501`。

顺序不能反：先起后端，前端才连得上。

## 7. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 侧边栏红字「连不上后端」 | 后端没起，或端口不是 8000 | 起后端；或设 `API_BASE_URL` |
| 上传后一直转圈 | 文件大 / 网络慢 | 等；看后端终端的日志 |
| 答案说「资料中没有相关信息」 | 库里没有相关内容 | 先上传对应文档 |
| 改了代码页面没变 | Streamlit 有缓存 | 右上角菜单 → Rerun |

---

## 8. 面试可以怎么讲

> 前端用 Streamlit 快速搭原型，只通过 HTTP 调后端接口，不直接访问数据库和模型。
> 这样后端可以独立部署、独立扩容，前端也能随时替换成正式框架。
> 侧边栏实时展示入库块数，方便验证每次上传是否真的落库。
