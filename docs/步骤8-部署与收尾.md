## 0. 本步产出

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 把项目 + 依赖打成一个镜像 |
| `docker-compose.yml` | 一条命令起「后端 + 前端 + 数据卷」 |
| `.dockerignore` | 打包时排除垃圾文件，镜像更小更快 |
| `README.md` | 项目门面：效果、架构、快速开始、面试话术 |

## 1. 先懂三个词（不用背，理解就行）

| 词 | 类比 | 说明 |
|---|---|---|
| 镜像 image | 装机前的系统光盘 | 只读模板，包含 Python + 依赖 + 你的代码 |
| 容器 container | 装好系统正在运行的电脑 | 镜像跑起来就是容器，可以起很多个 |
| 数据卷 volume | 外接硬盘 | 容器删了，挂载的数据还在 |

一句话：**镜像是菜谱，容器是照着菜谱做好的一盘菜，数据卷是冰箱。**

为什么必须挂数据卷？因为容器一删，里面写入的文件全没了。向量库和上传的文档必须放在宿主机上。

## 2. Dockerfile 逐段讲

```dockerfile
FROM python:3.13-slim
```

- `FROM` = 基于哪个底包。
- `slim` = 精简版，没有编译器、文档这些没用的东西。
- 为什么是 3.13 而不是最新版：numpy/chromadb 还没给 3.15 出轮子，装上会报错——这个坑你在本地已经踩过一次了。

```dockerfile
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1
```

- `PYTHONUNBUFFERED=1`：日志立刻输出，不攒着。不设的话，`docker logs` 会看不到实时日志。
- `PYTHONDONTWRITEBYTECODE=1`：不生成 `.pyc`，少一堆垃圾文件。

```dockerfile
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

- **先拷依赖清单，再装依赖，最后才拷代码。**
- 这是 Docker 的核心技巧：每一层都有缓存。你改代码时，依赖层没变，直接复用缓存，重建只要几秒。
- 反过来写（先拷代码再装依赖），改一行代码就要重装所有依赖，每次几分钟。

```dockerfile
COPY app ./app
COPY scripts ./scripts
COPY data/raw ./data/raw
```

- 只拷运行需要的东西。`tests`、`docs` 在 `.dockerignore` 里被排除了。

```dockerfile
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

- `--host 0.0.0.0` 必须写。写 `127.0.0.1` 的话，只有容器自己能访问，宿主机进不来。
- 这是新手最常踩的坑。

## 3. docker-compose.yml 讲关键点

```yaml
services:
  api:
    build: .
    image: rag-kb:latest
```

- `build: .` = 用当前目录的 Dockerfile 构建。
- `image: rag-kb:latest` = 构建出来的镜像起个名字，前端复用。

```yaml
    env_file:
      - .env
```

- 把 `.env` 的变量注入容器。
- 镜像里**没有** `.env`（在 .dockerignore 里），密钥永远不会被烤进镜像。

```yaml
    volumes:
      - ./data:/app/data
```

- 左边是宿主机目录，右边是容器内路径。
- 向量库写在 `/app/data/chroma`，实际落在你电脑的 `./data/chroma`。
- 容器重建，数据还在。

```yaml
  ui:
    image: rag-kb:latest
    command: [streamlit, run, app/ui/app.py, ...]
```

- 同一个镜像，换一条启动命令。
- 好处：不用维护两个 Dockerfile，依赖只装一次。

```yaml
    environment:
      API_BASE_URL: http://api:8000
```

- **容器之间用服务名互访**，不是 `localhost`。
- 在容器里 `localhost` 指的是它自己，不是宿主机，也不是另一个容器。
- compose 会自动把服务名 `api` 解析成那个容器的 IP。

```yaml
    depends_on:
      api:
        condition: service_healthy
```

- 等后端健康检查通过，再启动前端。
- 不然前端先起来，会先闪一下「连不上后端」。

## 4. .dockerignore 为什么重要

```
.venv
.git
__pycache__
.env
docs
tests
data/chroma
```

- `.venv` 里是给 Windows 用的二进制包，拷进 Linux 镜像不但没用，还会让镜像大几百 MB。
- `.env` 是密钥，绝不能进镜像。
- 不写这个文件，Docker 会把你整个目录（包括 `.venv`）先打包发给守护进程，慢到怀疑人生。

## 5. 在 Windows 上装 Docker

1. 打开 <https://www.docker.com/products/docker-desktop>
2. 下载 **Docker Desktop for Windows**
3. 安装，过程中会要求启用 WSL2（Windows 的 Linux 子系统），同意并重启
4. 装完打开 Docker Desktop，等左下角变绿（引擎启动）
5. 终端验证：

```bash
docker --version
docker compose version
```

两个都有版本号，就可以用了。

> 注意：Docker Desktop 要求 Windows 10 2004 以上或 Windows 11。
> 公司电脑可能没有管理员权限，装不上就先跳过，用本地方式启动也能演示。

## 6. 部署与验收

```bash
# 构建并后台启动
docker compose up -d --build

# 看状态（两个都应该是 running / healthy）
docker compose ps

# 看日志
docker compose logs -f api

# 停止（保留数据）
docker compose down

# 停止并删除数据卷挂载的文件（慎用）
docker compose down -v
```

验收清单：

- [ ] `docker compose ps` 里 api 是 healthy
- [ ] 浏览器打开 `http://localhost:8000/docs`，能看到 5 个接口
- [ ] `http://localhost:8501` 打开前端，侧边栏显示「后端已连接」
- [ ] 上传一份 PDF，返回块数
- [ ] 提问能返回答案 + 来源页码
- [ ] `docker compose down` 后再 `up -d`，之前入库的文档还在（验证数据卷）

最后一条最重要——它就是「数据卷到底有没有生效」的证明。

## 7. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 构建卡在 pip | 网络慢 | 已在 Dockerfile 里用清华源 |
| `port is already allocated` | 端口被本地服务占用 | 先关掉本地 uvicorn / streamlit |
| 前端显示连不上后端 | `API_BASE_URL` 写成了 localhost | 容器内要写 `http://api:8000` |
| 上传后重启容器数据没了 | 没挂 volume | 检查 `volumes: - ./data:/app/data` |
| 镜像 2GB+ | 没写 .dockerignore | 确认 `.venv` 被排除 |

## 8. 简历可以这么写

> 使用 Docker 多阶段（依赖层与代码层分离）构建镜像，通过 docker-compose 编排 API 与前端服务；
> 数据以 volume 挂载实现容器无状态化，重建容器不丢向量库；配置经 env_file 注入，密钥不落镜像。

三句话，把「会用 Docker」变成「懂为什么这么做」。
