## 0. 本步在整体流程里的位置

```
解析（步骤2）→ 分块（步骤3）→ 【本步：向量化 + 入库】→ 检索（步骤5）
```

- 向量化：把一段文字变成一串数字（向量）。
- 入库：把向量存进 Chroma，随存随取。
- 好消息：本步**不需要** API key、不需要显卡、不需要联网。
- 因为测试用一个「假向量工具」就能全部验证。

## 1. 先认识 4 个新写法

| 写法 | 意思 | 生活类比 |
|---|---|---|
| `Protocol` | 只规定「要会什么」，不管你是谁 | 岗位要求：会开车就行，不看学历 |
| `hashlib` | 把任意文字压成固定的一串字节 | 榨汁机：橙子苹果进去，都变统一规格的汁 |
| `sorted(东西, key=...)` | 按规则排序 | 按身高排队 |
| `{**字典}` | 把字典摊开合并 | 把两个袋子倒进一个大袋子 |

## 2. embedder.py：把文字变向量

### 第 1 段：接口约定

```python
class Embedder(Protocol):
    def embed_documents(self, texts: list[str]) -> list[list[float]]: ...
    def embed_query(self, text: str) -> list[float]: ...
```

- `Protocol` 只是「要求」，不干活的。
- 要求就两条：会「批量转向量」，会「单句转向量」。
- 谁能满足这两条，谁就**算**一个 Embedder。
- 好处：以后换模型，上层代码一行不改。

### 第 2 段：FakeEmbedder（测试专用）

```python
digest = hashlib.sha256(text.encode("utf-8")).digest()
return [digest[i % len(digest)] / 255.0 for i in range(self.dim)]
```

- `sha256` 把任意文字压成一串固定字节。
- 字节除以 255，变成 0~1 之间的小数。
- 关键性质：**相同文字 → 相同向量**。
- 测试就利用这一点：查询和某个 chunk 文字一样，向量就一样，检索必然排第一。
- 不联网、不花钱、结果稳定——测试的三大美德。

### 第 3 段：DashScopeEmbedder（生产用）

```python
from openai import OpenAI
self._client = OpenAI(api_key=..., base_url=settings.llm_base_url)
```

- `import` 写在函数里面，叫**延迟导入**。
- 意思是：用到才拿，没装这个包也不影响其他代码跑。
- DashScope 提供了「OpenAI 兼容模式」，所以客户端直接用 openai 包。

```python
resp = self._client.embeddings.create(model=..., input=texts)
data = sorted(resp.data, key=lambda d: d.index)
```

- `create(...)` 就是发请求。
- `sorted(..., key=lambda d: d.index)` 按原来的顺序排回来。
- 接口有可能乱序返回，排序保证「第 3 段文字对应第 3 个向量」。

```python
for i in range(0, len(texts), self.BATCH_SIZE):
    out.extend(self._embed(texts[i : i + self.BATCH_SIZE]))
```

- API 一次最多收 10 条，多了报错。
- 所以按 10 条一批，分批送。
- `range(0, 30, 10)` 会产生 0、10、20，正好切三批。

### 第 4 段：小工厂

```python
def build_embedder(provider: str | None = None) -> Embedder:
    provider = provider or settings.embedding_provider
```

- 工厂模式：传入名字，返回对应工具。
- 上层代码只调 `build_embedder()`，不用关心具体是谁。
- 想换实现？改 `.env` 一行就行（又是「改参数不改代码」）。

## 3. vector_store.py：存向量、查向量

### 开头那个常量

```python
_COSINE = {"hnsw:space": "cosine"}
```

- **全书最重要的一个坑**：Chroma 默认用 L2（直线距离）。
- 文本向量应该用 cosine（余弦，比「方向像不像」）。
- 不设置的话，代码不报错，但检索质量悄悄变差——最阴险的 bug。
- 我们显式设置了，并且写了个测试盯着它。

### add_chunks：入库

```python
ids = [f"{c.doc_name}#{c.page_no}#{c.chunk_index}" for c in chunks]
```

- 列表推导式：对每个 chunk 生成一个 id。
- `#` 只是分隔符，像「3号楼#2层#5号房」。
- 三个信息拼一起，天然不会重复。

```python
documents = [c.text for c in chunks]
metadatas = [c.to_metadata() for c in chunks]
```

- documents：存完整文本，检索到了要拿去拼答案。
- metadatas：存页码等小信息，回答「出自哪一页」用。
- 这就是步骤 3 里 `to_metadata()` 的用途兑现。

### search：检索

```python
res = self.collection.query(query_embeddings=[query_embedding], n_results=k)
```

- 传入查询向量，让它找最近的 k 条。
- 注意 `query_embeddings` 是**复数**，要包一层列表。
- 返回结构是「查询的列表」套「结果的列表」，所以到处是 `[0]`。

```python
{
    "id": res["ids"][0][i],
    "text": res["documents"][0][i],
    "distance": res["distances"][0][i],
    **res["metadatas"][0][i],
}
```

- `distance` = 距离，越小越相似。
- `**res["metadatas"][0][i]` 把字典摊平合进来。
- 最后每个结果长这样：
  `{id, text, distance, doc_name, page_no, chunk_index, context_prefix}`

### count / clear

- `count()`：库里几条。验收时先看它。
- `clear()`：清空重来。改了分块参数重新入库前，先清一下。

### ingest_file：一条龙

```python
chunks = chunk_file(path)
embeddings = embedder.embed_documents([c.text for c in chunks])
return store.add_chunks(chunks, embeddings)
```

- 三行 = 前三步全走完。
- 步骤 6 的「上传文档」接口，就调这一个函数。

## 4. 测试为什么这样设计

六个测试，各自盯一件事：

| 测试 | 盯什么 |
|---|---|
| add_and_count | 存得进、数得对 |
| search_exact_match | 相同文字必排第一、距离为 0 |
| metadata_roundtrip | 页码、前缀等不丢失 |
| top_k_limits | 要几条给几条 |
| persistence | 重启后数据还在（落盘） |
| clear | 能清空 |

- 全部用 FakeEmbedder：不联网、不要 key、0.01 秒跑完。
- 真模型的语义准不准，那不是这段代码要管的——**分层测试**思想。

## 6. 一个重要的技术决策（面试可讲）

原方案是本地 BGE-Large-ZH 向量化。本步改为默认走 DashScope 云端 API，原因：

1. 你的 Python 是 3.15.2，torch 还没有适配版本，本地模型装上就报错；
2. torch 约 2GB，下载慢、占空间；
3. API 有免费额度，速度快，代码一样简单。

但代码留了「可插拔」接口（`build_embedder` 工厂 + Protocol），
等 torch 适配后，加一个 `LocalBGEEmbedder` 类就能切回本地，其余代码零改动。
这叫**面向接口编程**，是面试加分点。
