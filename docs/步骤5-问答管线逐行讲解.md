# 步骤 5 代码逐行讲解：《问答管线》在做什么

> 配合 `app/rag/prompt.py`、`app/rag/llm.py`、`app/rag/qa.py` 一起看。
> 看不懂某一句，直接把那一句复制给助手问。

---

## 0. 本步在整体流程里的位置

```
解析 → 分块 → 入库 → 【本步：提问 → 检索 → 拼 Prompt → 大模型回答 → 标引用】
```

- 前四步都在「准备资料」。
- 这一步才是用户真正感受到的「问答」。
- 三个文件分工：
  - `prompt.py`：怎么把资料「摆」给模型看。
  - `llm.py`：怎么跟模型说话。
  - `qa.py`：把检索、拼装、提问、解析引用串起来。

---

## 1. 先认识 5 个新写法

| 写法 | 意思 | 生活类比 |
|---|---|---|
| 依赖注入 | 工具从外面传进来，不在里面自己造 | 厨师用你给的锅，不自己买 |
| `@dataclass` | 自动生成「装数据的类」 | 预制表格，填数就行 |
| `re.compile(r"\[(\d+)\]")` | 提前编好一个「找编号」的规则 | 提前背好暗号 |
| `time.perf_counter()` | 高精度计时器 | 秒表 |
| `field(default_factory=list)` | 默认给一个「空列表」 | 每人发一个新的空篮子（不是共用一个） |

最后一条要特别注意：默认值写 `= []` 会让所有对象共用一个列表，是个经典坑；
`default_factory=list` 才是「每个对象各自一个新的」。

## 2. prompt.py：引用编号协议（本步的灵魂）

```python
blocks.append(f"[{i}] 来源：{hit['doc_name']} 第{hit['page_no']}页\n{hit['text']}")
```

- `enumerate(hits, start=1)` 从 1 开始编号。
- 每块资料前面贴一个「[1] 来源：员工手册.md 第3页」。
- 模型看得到编号，就能在回答里引用编号。

```python
user_content = f"【资料】\n{build_context(hits)}\n\n【问题】\n{question}"
```

- 资料在前，问题在后。
- 这是 RAG 的标准摆法：先给证据，再问问题。

**system 里那四条规则，每一句都在防一件事：**

| 规则 | 防什么 |
|---|---|
| 只用资料回答 | 防模型用自己知识瞎答 |
| 结论后标 [编号] | 让答案可追溯 |
| 资料不足就说没有 | 防硬编答案（幻觉） |
| 不要照抄原文 | 防止把整段资料复制一遍 |

## 3. llm.py：真客户端 + 假客户端

```python
resp = self._client.chat.completions.create(
    model=self.model, messages=messages, temperature=0.1,
)
```

- `temperature=0.1`：接近 0 就是「照资料说」，不发挥。
- 问答场景要稳定，不要创意。

```python
class FakeChat:
    def chat(self, messages):
        self.last_messages = messages
        return self.reply
```

- 测试专用：不问内容，直接给预设答案。
- `last_messages` 记下收到的内容，测试才能断言「资料真的传进去了」。
- 好处：测试不联网、不要 key、0 成本。

## 4. qa.py：四步流水线

### 第一步：检索

```python
query_vec = self.embedder.embed_query(question)
hits = self.store.search(query_vec, top_k=k)
```

- 问题先变向量，再去库里找最近的 k 条。

### 第二步：空库兜底

```python
if not hits:
    return Answer(question=question, answer=NO_ANSWER_HINT)
```

- 库是空的，就别浪费一次模型调用。
- 直接回「资料中没有相关信息」——这也是防幻觉。

### 第三步：调模型

```python
messages = build_messages(question, hits)
raw = self.llm.chat(messages)
```

### 第四步：解析引用

```python
for m in _CITE_RE.findall(text):
    n = int(m)
    if 1 <= n <= len(hits) and n not in seen:
```

- `findall` 把答案里所有 `[数字]` 抓出来。
- 两道防御：
  1. **越界**：只给了 3 条资料，模型却标 `[9]` → 忽略。
  2. **重复**：`[1]` 出现多次 → 只记一次。
- 最后映射回真实来源：

```python
Citation(index=n, doc_name=hits[n - 1]["doc_name"], page_no=hits[n - 1]["page_no"])
```

- 为什么是 `n - 1`？因为人从 1 开始数，列表从 0 开始。

### 计时日志

```python
logger.info("问答完成 | hits={} retrieve={:.0f}ms llm={:.0f}ms cited={}", ...)
```

- 检索多久、模型多久，一眼看到。
- 以后优化性能，先看这条日志。
- 这也是工程化习惯：**可观测**。

## 5. 测试为什么这样设计

| 测试 | 盯什么 |
|---|---|
| prompt_numbers_every_source | 每块资料都有编号，问题和资料都在 |
| parse_citations_dedup_and_order | 去重、按出现顺序 |
| parse_citations_ignores_out_of_range | 越界编号被忽略 |
| pipeline_returns_answer_with_citations | 整条链路通，引用能对上文件页码 |
| pipeline_empty_store_returns_hint | 空库不瞎答 |

关键点：**没有一个测试调用真模型**。
CI 里跑测试永远稳定、免费、秒出结果——这是企业项目的硬要求。

## 6. 怎么真跑（需要两个 key）

**为什么是两个 key？**

- 问答要两件事：**理解问题**（向量化）和**写出答案**（对话模型）。
- DeepSeek 只提供「对话」，**没有 embedding 接口**（官方文档确认）。
- 所以：对话用 DeepSeek，向量化用硅基流动的 bge-m3（免费）。

1. 项目根目录的 `.env`（模板已生成），填两行：
   ```
   LLM_API_KEY=sk-DeepSeek的key
   EMBEDDING_API_KEY=sk-硅基流动的key
   ```
2. 终端里：
   ```
   python scripts/demo_ask.py
   ```
3. 观察：先入库示例文档（会调用 Embedding），然后提问「迟到怎么算？」
4. 输出应该带答案 + 来源页码。

注：`.env` 里 `LLM_MODEL=deepseek-flash`。如果提示模型不存在，改成 `deepseek-chat` 再试。

## 7. 面试可以这么讲（防幻觉三板斧）

1. **检索为空直接拒答**：不给模型「无米之炊」的机会。
2. **Prompt 强制只依据资料 + 必须标引用**：把「不许编」写进系统提示。
3. **后处理校验引用**：越界的编号直接丢弃，答案和来源必须对得上。

再加一句：「测试全部用假模型，不依赖外部服务，所以能进 CI。」
这句话很值钱。
